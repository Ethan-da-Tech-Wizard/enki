# Two-minute demo

1. Open the local app. Explain that Access Lab is an independent prototype with a fictional team, sample pricing, and simulated payments.
2. As Maya, identify the blocker: all five purchased seats are occupied. Request access. The request is saved and the administrator is notified in-app.
3. In the separate demo controls, select Eli. Review the request. Explain $12 × 15 / 30 = $6 now and 6 × $12 = $72 next period. Approve.
4. Return to Maya and open the sample workspace. Explain that the server checks membership and an assigned seat before returning it. The preview illustrates access; it is not a complete code-review product.
5. For a longer demo, reset and choose payment failure before approving. Show the recoverable request, unchanged seat count, and no successful charge. Set the outcome to success and deliberately retry.
6. Open the evidence links. Explain which decisions came from public sources, which are simplified demo rules, and which behaviors have been tested.

Useful questions to be ready for: Why this user problem? Why this scope? What happens on failure or repeat clicks? What did you personally decide? How would you validate usefulness? What would change for real payments and production identity?
